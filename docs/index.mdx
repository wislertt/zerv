**Dynamic versioning from git. Every commit gets its version.** Generate semantic versions from
any commit across all branches, or a dirty working directory, with pre-release handling and
format support for any CI/CD workflow.

## Why zerv?

- **Runs next to [semantic-release](/cicd/semantic-release)** - semantic-release decides
  releases on main; zerv versions every other build: any commit on any branch, even with
  uncommitted changes. No build is ever unversioned.
- **Two modes** - [`zerv flow`](/concepts/flow) automates pre-release management from Git
  branch patterns; [`zerv version`](/concepts/version) gives full manual control with
  schemas, overrides, and templates.
- **Any output format** - SemVer, PEP440, CalVer, or
  [Tera templates](/concepts/formats-and-templates). Generate every format your pipelines
  need from a single ZERV RON payload.

Read [why zerv](/getting-started/why-zerv) for the positioning story, including when to
reach for something else.

## A taste

```bash
# The current branch determines the output; no config required
zerv flow
# → 1.0.0 (on main branch with tag v1.0.0)
# → 1.0.1-rc.1.post.3 (on release branch with pre-release tag)
# → 1.0.1-beta.1.post.3+develop.3.gf297dd0 (on develop branch)
# → 1.0.1-alpha.59394.post.1+feature.new.auth.1.g4e9af24 (on feature branch)
# → 1.0.1-alpha.17015.post.1.dev.1764382150+feature.dirty.work.1.g54c499a (on dirty feature branch)
```
