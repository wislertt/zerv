# zerv docs

The documentation site for [zerv](https://github.com/wislertt/zerv), deployed at
[zerv.wisl.dev](https://zerv.wisl.dev) via the Mintlify GitHub integration.
No CI workflow in this repo deploys it.

## Local development

```bash
bake docs
```

Runs a hot-reload Mintlify dev server on <http://localhost:3000>. Check for
broken links with `bake docs-check`.

## Structure

- `docs.json`: Mintlify config (navigation, colors, logo, favicon, footer)
- `custom.css`: hero/badge styling for the index page
- `index.mdx`: landing page
- `getting-started/`, `concepts/`, `cicd/`, `cli/`, `examples/`, `troubleshooting/`: pages
- `img/brand/`: committed brand assets, generated by `scripts/branding/` (see `scripts/branding/README.md`)

## Conventions

- Code examples must carry a `{/* Corresponding test: ... */}` comment and a
  backing test; see `.claude/ref/documentation-maintenance.md` and
  `tests/integration_tests/docs/`.
- Adding a page: create the `.mdx` file and register its path under
  `navigation.groups` in `docs.json`.
- `skill.md` is hand-written and served at `/skill.md`; it overrides the
  low-quality file Mintlify auto-generates. Do not delete it. It is served raw,
  so it cannot carry `{/* Corresponding test: ... */}` comments — every code
  example in it must be a verbatim copy of a tested `.mdx` example.
- `markdown.instructions` in `docs.json` is injected as an `Agent Instructions`
  block into `llms.txt` and every Markdown page export.
